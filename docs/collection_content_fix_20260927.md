## 修正内容

- `collection_content.py`: イベントAPIの省略説明を`api_description`に保存し、公開個別回答の全文を上書きしない。全文の取得元・取得時刻を保存する。
- `scraper.py`: `details_fetched=True`でも現在公開中の全チケットを補完する。公開個別APIは2並列、要求後0.5秒待機、既存25分制限・100件ごとの保存を維持。公演/IDの検証と同一実行内の照会結果再利用を行う。
- `collection_evidence.py`: 公開回答の枚数・日時・会場・券種・名義・受渡し・座席・出品者・説明文を対応列へ保存する。古いキャッシュ、異なるID/公演、異常な枚数で既存内容を壊さない。
- inactive/pausedは最後のactive観測時刻を捏造しない。最近公開照会できた停止中チケットは36時間後も更新候補へ残す。
- 変更JSONLは本当の値の変更を記録し、確認時刻/取得元だけの変化では全文を毎回重複保存しない。
- `tools/audit_public_content.py`: 全active行の全文provenance・鮮度・公演IDを監査。公開内容/停止中状態の照会失敗・未処理を検出する。実サイト標本照合も可能。
- GitHub Actionsはデータを保存後に全文品質ゲートを実行する。補完不完全を成功としない。部分取得データは保存され、次回取得で補完できる。
