# 2026-10-06 Actionsの一時障害と復旧対応

## 確認した原因

直近100実行（収集50回とバックアップ50回）では、それぞれ1回の失敗を確認しました。

1. 収集: 2026-10-06 05:00（日本時間）開始の
   [実行37367069889](https://github.com/hiro8-0215/tiketen_scraper/actions/runs/37367069889)は、
   `The job was not acquired by Runner of type hosted even after multiple attempts`
   というGitHubの失敗注釈で終了しました。runner_idは0、実行ステップは0件で、
   スクレイパーは起動していません。コードからGitHubのホストランナー不足を解消することは
   できないため、最新mainから再実行して復旧を検証します。ランナー起動前の失敗は
   ワークフロー内の再試行処理でも救済できません。
2. Drive: 2026-10-06 03:27（日本時間）開始の
   [実行37356114734](https://github.com/hiro8-0215/tiketen_scraper/actions/runs/37356114734)で、
   `ae-group_master.csv`の送信がHTTP 404およびJSONではない応答により5回失敗しました。
   最初のファイルは送信でき、次の通常バックアップは成功しています。恒久的な認証エラー
   より一時的なApps Script/Google側の応答障害を示す状況です。

前回対策した100 MB制限によるpush拒否は、この調査範囲では再発していません。

## 修正内容とデータへの影響

- 1ファイル内の再試行間隔を1/2/4/8秒から10/20/40/60秒へ延長します。
- HTTP 404、408、429、5xx、通信タイムアウト、JSONとして解釈できない応答などの
  一時エラーが5回続いた場合は、そのファイルを保留して他のファイルを保存します。
  60秒後と120秒後に、失敗したファイルのみを最大2回の追加パスで再試行します。
- 保存済みのファイルを追加パスで再送しません。全ファイルの保存に成功したときだけ
  `Google Drive backup completed.`を出し、未保存ファイルが残れば失敗を報告します。
- 全体に15分の時間予算を設け、待ち時間と通信タイムアウトを残り時間で制限します。
  バックアップジョブの20分上限を維持します。
- 401/403、ファイル容量超過、Apps Scriptの明示的な拒否などは追加パスへ回さず、
  対処が必要なエラーとして終了します。
- CSVの列・値、JSONLの形、ファイル名、保存先フォルダは変更しません。
  GitHub SecretsやApps Scriptの再デプロイは今回のクライアント側修正に不要です。

一時障害を必ず解消できる保証はありません。15分の時間予算を超えてサービスが
復旧しない場合は、成功したファイルを保存した状態でジョブを失敗にし、再実行を促します。
収集の成功とDriveバックアップの成功は別々に確認してください。

## 検証

```bash
python -m unittest discover -s tests -q
```

一時エラーの分類、失敗したファイルのみの再試行、永続エラーの即時終了、保存に失敗した
状態で成功を報告しないこと、時間予算と通信タイムアウトを回帰テストで確認します。
push後はGitHub上で収集とDrive保存を実行し、各ステップと全ファイルの保存結果を確認します。
