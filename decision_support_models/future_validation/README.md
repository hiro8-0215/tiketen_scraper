# 3モデル将来期間検証

9月7日までに学習した保存済みの需要・代替チケット出現・買い時モデルを、それ以後のスナップショット対で検証する。入力には前の日の保存値、結果には後の日の保存値を使う。学習済みモデルの更新はしない。

VS Codeのローンチは次の4つ。

- `[25 3モデル検証][0 確認]`:　9月7日後のスナップショット、イベント更新とモデルを監査する。
- `[25 3モデル検証][1 完全実行]`:　不足するLLM意味特徴のみを追加し、各入力日のModel16価格を生成してから保存済みモデルを評価する。最初はこれを実行する。
- `[25 3モデル検証][2 準備済み実行]`:　意味特徴が入力日・結果日の両方に揃っている場合だけ使う。入力日のModel16価格は毎回生成する。
- `[25 3モデル検証][3 結果表示]`:　最新の完了済み結果を再表示する。

保存済みモデル・手動マスタ・対象スナップショットのSHA-256を実行前後で比較する。イベント単位の監査を`collection_audit.json`へ保存し、3モデルの結果・単純予測との比較・確率補正候補を`strict_report.json`へ保存する。比較候補は保存済みモデルへ自動適用しない。

旧データにはイベントごとの連続取得ログと、新規出品の初回観測日時の証明がない。この期間の代替出現の陽性・陰性は原則として未確定になる。新しいスクレイピングから`observation_YYYYMMDD.jsonl`と`first_observed_source`を収集する。sold遷移が未収集なら売却予測および買い時の方針比較は`insufficient_evidence`と表示する。古いデータを消す必要はない。

既存の2026-09-18結果は古い評価方式で、最終観測後をactiveと扱っていたため、`[3 結果表示]`には明確な注意を表示する。新しい完全実行後に厳密結果へ切り替わる。
