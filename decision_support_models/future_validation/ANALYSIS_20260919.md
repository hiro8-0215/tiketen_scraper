# 3モデル将来検証の分析と改善方針（2026-09-19）

対象: artifacts/20260918_190252_258342。学習終了観測時点2026-09-07 12:01:15、評価データ最終時点2026-09-18 04:01:08。モデルの再学習・LLM生成は本分析では実施していない。

## 結論

検証処理は完了しているが、この結果をモデル性能の確定値として採用してはいけない。需要の正解ラベルに、個別の最終観測以降を全体の観測終了日まで「出品中」とする問題がある。代替の「出現なし」もイベントの収集継続を確認せずに付与している。先の「需要1・3日は良好」「代替1日は有効」という評価は撤回する。まず観測範囲と評価ラベルを修正し、その後にモデル改善を判断する。

## 最優先の問題: 観測されていない期間のラベル

需要timeline.pyのadd_end_timesはknown_untilを全チケット共通cutoffで初期化し、listingについて個別last_observed_atを上限としていない。

既存ローダーで読み込んだ9月18日のlisting 3,043件の最終確認日は以下。

- 8月30日: 60件
- 9月3日: 1件
- 9月4日: 1,961件
- 9月5日: 42件
- 9月11日: 934件
- 9月18日: 45件

保存済み需要予測をローダーのticket_idと結合して調べると、判定期限が個別last_observed_atを超えるlistingが1日25,922行、3日20,184行、7日8,708行ある。3日・7日のactive正解行はすべてこの条件に当てはまる。行数はチケット×予測時点×期間であり、独立したチケット数ではない。

これは「新規データが0」ではなく、「データは増えているが既存出品の状態更新が十分観測できていない」という問題。旧データを削除する必要はない。再確認できない期間を未観測として扱う必要がある。

代替timeline.pyも全体cutoff以前ならfully_observedとする。あるイベントの収集が止まっていても、別イベントの更新があるだけで「出現なし」を付与し得る。正の出現記録と、出現しなかったことを保証できる期間を区別すべきである。

## 収集と評価の追加の問題

1. raw sold件数は9月7日・13日・18日とも4,131件。sold最終観測の最大値も9月5日00:01:13で不変。APIのsold返却、実際に配備されたコード、イベント取得範囲、保存ファイルの継承を確認する必要がある。ローカルscraperにはsold更新処理とactiveOnly=0が存在するが、本番で同じコードが成功実行された証拠にはならない。
2. 最新スナップショットの説明・価格・手動マスタを過去の判定時点へ戻して使用しているため、厳密な当時情報による検証ではない。9月13日等の保存済み中間スナップショットを使い、判定時点で利用可能な値を採用する。
3. scraperの新規行にはAPI createdAtをfirst_observed_atへ設定する箇所がある。作成日時と収集側の初回確認日時は別であり、初回取込時に過去の観測が存在したと仮定しない設計が必要。
4. 需要7日OOFは60行でactiveが0件だった。校正・モデル選択の根拠が弱く、長期予測への拡張を支持しない。
5. 需要・代替の市場特徴は終了時刻がないlistingを出品中として扱う。古いlistingが市場在庫や価格分布に残る問題はラベル修正だけでは解決しない。

## 改善の順序

1. 保存済み各日の状態・last_observed_atを比較し、イベント別に更新が止まった時点を特定する。本番実行ログと取得対象を照合する。deletedをsoldへ置き換えない。
2. 需要は各出品の確認できる期間を上限として打ち切り、最後の確認後をactiveと断定しない。代替はイベント単位の収集成功期間を保証できない場合、非出現ラベルを未確定にする。日次ファイルだけで厳密に保証できない期間は、その限界を記録する。
3. 判定時点の入力を凍結し、9月13日入力→18日結果など保存済みスナップショット対で評価する。1日・3日・7日のどれが確認可能かを先に数える。5日差だけでは1日・3日の厳密な発生時刻が分からないケース、7日の観測不足を分ける。
4. 修正したラベルで保存済みモデルを再評価する。active/非出現固定予測と、学習期間で定めた一定確率予測を併記する。日次の反復行に加えてチケット数とイベント数を報告する。
5. その結果で確率の過大推定が残る場合に、過去期間だけでの再校正、期間別校正、出品経過日数による母集団差の対処を比較する。検証期間の正解で調整した設定を同じ期間で最終評価しない。
6. 需要・代替の確率が確認できた後、買い時方針を時系列で再選定する。常に買う・常に待つとの比較を必須にし、sold不足の期間だけで待機推奨を最適化しない。

今回の分析からはModel16価格モデルを再学習する必要性は示されない。最優先は3モデルに渡す観測履歴と検証方法の是正である。既存モデル・意味特徴は保持し、再生成が必要な範囲を後で判断する。
